==================================================
NEXT MODULE
CROSS-SOURCE CONTRADICTION ENGINE
==================================================

ShadowWatch currently detects missing evidence.

Now it must also detect cases where DIFFERENT SOC records disagree
with each other.

This is important because supervisory assessment should not trust
one table/record in isolation.

Example concept:

CASE RECORD:
Status = CLOSED

INVESTIGATION RECORD:
Investigation not completed

These records contradict each other.

Another example:

CASE:
Closed at 10:05

INVESTIGATION:
Completed at 10:30

The investigation apparently finished AFTER the case was already
closed.

This should be surfaced for supervisory review.

==================================================
CONTRADICTION CATEGORIES
==================================================

Implement only contradictions supported by the real data.

Potential examples:

C001 - CASE_CLOSED_BEFORE_INVESTIGATION_COMPLETED

Condition:

case.closed_at < investigation.completed_at

Meaning:

The case record says the case was closed before its investigation
was completed.

--------------------------------------------------

C002 - INVESTIGATION_BEFORE_CASE_OPENED

Condition:

investigation.started_at < case.opened_at

Meaning:

Investigation timestamps indicate activity before the associated
case existed.

--------------------------------------------------

C003 - ESCALATION_AFTER_CASE_CLOSED

If supported:

escalation.escalated_at > case.closed_at

Meaning:

The escalation was recorded after the case was already closed.

--------------------------------------------------

C004 - ALERT_AFTER_CASE_OPENED

If supported:

alert.timestamp > case.opened_at

Meaning:

The case appears to have been opened before the alert that created
it.

--------------------------------------------------

C005 - CLOSED_CASE_WITH_INCOMPLETE_INVESTIGATION

ONLY implement this if the schema contains a reliable investigation
completion/status field.

Do not infer unsupported status values.
